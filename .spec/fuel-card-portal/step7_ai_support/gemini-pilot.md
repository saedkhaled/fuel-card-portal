# Gemini pilot for Arabic Support

Status Planned · Baseline `5a3719d` on `codex/fuel-card-portal` · 25 November 2026

## Pilot scope

Use Gemini Developer API with `gemini-3.5-flash-lite` for natural Arabic replies and brief follow-up questions. Use the same 58-passage [knowledge base](../../../assets/demo/standard/support.json) as the current offline tab. Use public Golden Gate information and synthetic questions for live free-tier testing. Include a guide excerpt in the provider payload only if it is approved for external sharing. Use a synthetic counterpart for any other guide excerpt and keep its real source ID in the local evaluation fixture. The offline catalog and its FAQ remain available for the whole pilot.

Create a dedicated free-tier AI Studio project and API key. Check the model and quota in that project before the live run. Google lists Syria as a supported region and may use unpaid-tier inputs and outputs to improve its products. Run the pilot locally with a test key and synthetic data. A customer rollout is a separate decision that needs real app authentication and a provider data-handling review. [Gemini model](https://aistudio.google.com/docs/models/gemini-3.5-flash-lite) · [Pricing](https://aistudio.google.com/docs/pricing#gemini-3.5-flash-lite) · [Project limits](https://aistudio.google.com/docs/rate-limits) · [Regions](https://aistudio.google.com/docs/available-regions) · [Free-tier terms](https://aistudio.google.com/docs/terms#unpaid-services)

## Implementation sequence

1. Add a small Python backend with `POST /support/answer` and an injectable Gemini client. Bind the pilot server to host loopback. Use Android `adb reverse tcp:8080 tcp:8080` for development and scope loopback HTTP to the Android debug configuration. A deployed build uses an authenticated HTTPS backend. Read `GEMINI_API_KEY` from the server environment or secret store. The Flutter app receives the endpoint address and keeps the existing offline behavior when no endpoint is configured. [API key guidance](https://aistudio.google.com/docs/api-key#critical-security-rules)
2. Send a question of up to 300 characters and, when relevant, an allowlisted passage ID from the previous answer. Keep draft text and the transcript in Flutter. Validate the request on the server and filter sensitive inputs before any provider call. Use the catalog schema and ranking fixture checks to select up to four relevant excerpts by stable ID. Keep account data, card numbers, OTPs, and payment identifiers outside provider requests. Handle personal balances and actual payment status locally with the appropriate portal route. Use the official portal link for live fuel availability.
3. Request structured JSON with `status` (`answer`, `clarify`, or `no_answer`), `text`, and `sourceIds`. Use Arabic by default and support an explicit English request when the selected sources cover it. Treat questions and passages as data with no tool permissions. Instruct the model to answer from the excerpts, ask a focused question where it can resolve ambiguity, and avoid making claims about live stock or accounts. Validate the output shape, require at least one retrieved source ID for an answer, and resolve destinations from the catalog. Use reviewed catalog wording for payment procedures, fees, and live-availability guidance. Use stored local text or the FAQ for invalid output. Source ID validation establishes provenance. Correctness is checked separately against the expected facts in the evaluation. [Structured outputs](https://aistudio.google.com/docs/structured-output)
4. Keep the searching indicator visible while the connected answer is pending. Use a single request per send and start with an eight-second end-to-end deadline. Return to the existing local search on timeout, connection failure, quota exhaustion, or a rejected response. Discard late results on sign-out and block concurrent sends from the same composer. Set a pilot request cap below the project quota. Log request IDs, result class, timing, model, and catalog version. Keep question text, transcripts, response text, and secrets out of pilot logs.

## Verification sequence

- [ ] **Credential-free tests.** Use a fake Gemini client and deterministic Flutter responses. Check catalog retrieval and source rendering, JSON validation, nonexistent and unretrieved citation IDs, malformed responses, no usable evidence, conflicting sources, and instruction-like text in a question or passage. Assert that sensitive synthetic requests and unsupported local routes use zero provider calls. Verify that the endpoint without a valid test configuration fails cleanly and that the app's offline default makes zero network calls.
- [ ] **Live opt-in smoke.** Supply the test key in the server environment and run the synthetic cases below through the local backend with the real model. Start with one request per case and use fake failures for rate-limit testing. Compare expected facts and source IDs against the reply. Record the model, catalog version and checksum, elapsed time, verdict, and any failed case. Use actual AI Studio quota before adding runs.
- [ ] **Installed Android check.** Run all Flutter tests and verify a connected debug build on Android. In Arabic, send a fresh question and a short follow-up, observe the searching indicator, inspect the guide citation, and open an official-source link. Test an English-language device with Arabic app defaults, RTL text with numbers, disconnect or airplane-mode fallback, a fake 429 and an eight-second deadline, and sign-out while the request is pending. Check V01, V07 and V08 from the [Android verification matrix](../verification.md).
